# 工作流与模块协同修复验证

日期：2026-10-24。范围为科研流程、项目待办、专家团队、定时任务、产物登记及执行恢复。

## 修复后的行为

| 场景 | 结果 |
| --- | --- |
| 项目选择自定义工作流 | 科研台导航、项目概览、看板和交付门槛统一使用所选 DAG；分支节点检查全部直接上游。 |
| 模型执行结束 | 成功执行进入待验收；只有实际产物有效且上游已交付时才能确认交付。空响应、空译文、失败、取消和达到工具调用上限均不会自动变成已交付。 |
| 已交付产物被修改或删除 | 内容指纹、文件哈希及上游交付版本触发失效；下游计划缓存按已确认快照更新。 |
| 待办派给专家 | 保存专家 ID，关联唯一执行任务；执行、产物、验收状态回写待办，重复派发被拒绝。工作流待办导入保持幂等。 |
| 定时任务关联待办 | 界面可选择项目待办；执行使用相应阶段上下文，记录输出资产和运行来源，成功后仍须交付验收。 |
| 导出、翻译及团队产物 | 登记可检索资产、输入输出关系和运行来源；历史版本保存独立文件，不随当前文件改写。 |
| 刷新或 SSE 断连 | 后台工作独立于 HTTP 连接；客户端按事件游标补取，同一请求不会重复执行。刷新恢复所选页面和工作流步骤。 |
| 停止及服务重启 | 停止信号传递到模型等待和写入边界；保存的模型边界可续接，已执行工具结果复用。工具执行结果不明时标为中断，要求核对后重试。定时任务旧运行记录不再永久停留在运行中。 |
| 项目笔记与数据重开 | 笔记入口保留正确子页；数据库同路径重建后重新初始化；每次打开数据库恢复 Zotero 来源保护。 |

## 升级及恢复语义

新增迁移 `010_workflow_coordination.sql` 保存待办与执行记录关联。旧的 `done` 执行记录没有已确认产物快照，升级后按待验收展示；用户确认现有产物后再解锁依赖阶段。

本地取消会停止继续处理和后续写入；已发出的远端请求是否终止仍取决于提供方。工具执行中的异常退出不自动重放，避免重复产生外部副作用。新增浏览器测试不代表已对所有远端模型、邮件或文献服务完成实时联调。

PR 基于目标仓库 `main`，保留本地原有的笔记树管理、聊天折叠、数据库并发及文档链接更新；通过重建提交链避免带入两仓库之间重复的历史提交。
