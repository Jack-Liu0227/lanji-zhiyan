## 5. 分层诊断

### 5.1 UI 与交互

**优点**：页面、导航、移动端能力弹窗、工作流布局、主题对比度和 DOM 引用均有自动化检查；轮询不会覆盖正在编辑的内容。  
**问题**：部分长任务仍依赖前端等待；错误提示、取消和重试入口没有统一模式；长文本/大图/大图谱性能尚无基准。

### 5.2 HTTP/API/SSE

**优点**：标准库 HTTP 服务、JSON API 和 `text/event-stream` 已能驱动 Agent 流式输出；异常会转为结构化错误。  
**问题**：当前 SSE 使用 close-delimited HTTP/1.0，没有 heartbeat、事件游标、Last-Event-ID、重连补偿和服务端事件持久化；客户端断开只捕获 `OSError`，后台任务仍可能继续消耗模型额度。

### 5.3 数据库与任务

**优点**：SQLite WAL 与 `busy_timeout=5000` 已开启；论文按页存储，SHA256 去重，证据写入前校验页码和原文片段。  
**问题**：翻译 `JOBS` 等部分状态为进程内内存；迁移主要为启动时补列，缺版本化 migration 表；多进程高并发和大事务没有压力基线。

### 5.4 MCP 与外部连接器

**优点**：配置保存不自动执行，显式发现工具；凭证保护和 reveal 语义清晰。  
**问题**：外部 MCP 子进程异常退出、stderr 膨胀、超时、僵尸进程、恶意工具描述和返回体大小尚未做压力/攻击测试；Zotero、RSS、Mail 等连接器缺统一熔断和速率限制。

### 5.5 安全与隐私

**已确认**：Windows DPAPI 保护 MCP 配置；敏感字段默认脱敏；Skill 路径约束；工具 allowlist 在服务端复核；证据必须包含页码和原文。  
**待加强**：日志字段全量脱敏审计、导出文件权限、路径符号链接/UNC 边界、HTML/Markdown 内容净化、外部链接 SSRF、上传文件类型和大小限制。

## 6. 问题分级

### P0（阻断）

当前未发现 P0。全量测试、运行时专项和前端自检均通过。

### P1（下一迭代必须修复）

1. **资源句柄关闭不完整**：`tests/test_papertran.py` 的子进程日志文件，以及浏览器服务运行时日志存在延迟关闭。应统一使用上下文管理器、`finally`、进程退出等待和日志轮转，并增加 `-W error::ResourceWarning` CI 门禁。
2. **SSE 不可恢复**：缺 heartbeat、事件持久化和 Last-Event-ID；网络抖动会导致用户看不到完整轨迹。应引入 `event_id`、`run_events` 表、重连游标和取消接口。
3. **Provider 弹性不足**：缺统一 connect/read timeout、指数退避、429/5xx 分类、熔断和预算上限。应在 `ai-runtime` 统一封装，禁止各调用点自行实现。
4. **长任务重启恢复不足**：下载/翻译/转换部分状态为进程内；应用关闭后无法可靠恢复。应将任务、分片、重试次数和取消状态落到 `tasks`/`task_attempts`。
5. **MCP 进程生命周期风险**：需要超时、最大输出、stderr 上限、优雅退出和强制回收；每个 server 应有并发信号量。

### P2（短期改进）

- SQLite 高并发写入基准、迁移版本表、备份/恢复校验和损坏检测。
- 大文件 PDF、扫描 PDF、LaTeX 编译器缺失、Windows 长路径的错误体验。
- 多助手并发会话的配额、token/cost 指标、上下文截断和 prompt 注入回放测试。
- 统一错误码、用户可读的重试/取消按钮、长任务进度百分比和可观察日志。
- 连接器的速率限制、缓存 TTL、ETag/If-Modified-Since 和上游 schema contract tests。

### P3（体验增强）

- 助手/Skill/MCP 配置导入导出、版本比较、变更审计。
- 更细的引用台账 UI、批量证据复核、图谱布局缓存和键盘可达性报告。
- Provider 成本面板、模型能力标签、上下文窗口预警和离线 mock provider。

## 7. 改进方案与验收指标

### 迭代 A：可靠执行底座（1 周）

- 新增 `tasks`、`task_attempts`、`run_events`、`idempotency_keys` 表；所有下载、翻译、转换和 Agent run 使用统一任务协议。
- `ai-runtime` 提供 `call()`、`stream()`、`cancel()`、`retry_policy`、`budget` 和 `telemetry`；禁止业务层直接拼接 HTTP 重试。
- SSE 改为 HTTP/1.1 长连接，15 秒 heartbeat；支持 `Last-Event-ID`、断线补发和客户端取消。
- 资源门禁：全量测试在 `-W error::ResourceWarning` 下无告警；子进程和日志句柄 100% 由 `finally` 回收。

**验收**：模拟断网 30 秒后恢复，事件不重复、不丢失；任务重启后从最近 checkpoint 继续；连续 1,000 次 run 无句柄增长。

### 迭代 B：外部依赖与安全（1-2 周）

- Provider/MCP/连接器统一 timeout、429/5xx 分类、退避、熔断、并发上限和最大响应体。
- 增加 SSRF 防护（禁止 loopback/私网目标，允许用户显式例外）、上传 MIME/大小/扩展名白名单和符号链接检查。
- 建立 `audit_events`，记录 actor、assistant、tool、project、input_hash、outcome、duration，不记录原始密钥。

**验收**：恶意工具名/描述、超大返回、异常退出、伪造调用均被拒绝；敏感值扫描在日志、SSE、错误响应中为 0 命中。

### 迭代 C：体验和规模（2-3 周）

- 统一任务卡片、错误码、取消/重试/恢复入口；大纲/正文采用版本号和乐观锁。
- 增加 100/1,000 篇论文、10 万页文本、1,000 节点图谱的性能基线。
- 增加真实 Provider 合约测试（默认 mock，CI 中可选 secrets 环境运行），不把第三方配额写入主 CI。

**验收**：P95 本地 API < 200 ms（不含模型），首个 SSE 事件 < 1 s；前端长任务无阻塞；内存和 SQLite 文件增长可解释。
