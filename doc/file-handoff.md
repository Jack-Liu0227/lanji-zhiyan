# 当前工作流内的文件交接

在科研平台选择文件，点击预览栏的「交给…」，或在文件、笔记列表中右键选择「交给当前工作流…」。文件列表和文件编辑器支持 `Alt+Shift+H`；快捷键帮助中可以查看或关闭。

三个查找入口共享同一个节点任务：

- **按节点**：使用节点已配置的执行者。
- **按团队**：只显示当前工作流引用的团队，再确定关联节点。
- **按助手**：只显示当前工作流有执行资格的助手。参与多个节点时，必须选择归属节点。

目标可通过下拉框选择，也可点击列表项。按团队选择节点后，若该节点允许多个成员执行，会显示「执行助手」下拉框；固定成员的节点不会开放换人。

兼容旧配置：旧版的三个内置工作流只保存了节点，执行成员保存在项目常驻团队中。未单独绑定执行者的内置节点会读取当前项目已有的对应常驻团队，通过稳定的角色 ID 和成员环节配置确定资格。团队、助手改名后仍可识别；不创建或恢复已删除的成员。自定义工作流仍须显式绑定节点执行者；显式绑定失效时不会回退到其他团队。打开目标面板保持只读。

更早版本还可能把团队负责人保存为“智研管家”，助手 ID 为空。启动时会迁移这类旧负责人绑定，保留成员 ID、现有任务、提示词和模型设置。若运行中导入旧配置，面板会显示「修复本项目团队绑定」；修复仅作用于当前项目，不启用已停用的助手。当前项目确实尚未建立团队时，面板提供「打开本项目团队配置」，初始化后返回刷新目标即可。

团队节点固定成员时不能换人；未固定成员时，只允许匹配当前环节、承担通用执行职责的成员或 Leader。审核人不能作为执行接收人。助手不存在、停用、团队归属其他项目或绑定冲突时，目标不可用。工作流设置中的「执行方式」明确区分助手与团队；文件交接不会回退到全局默认助手。

「准备任务」保存文件、执行者、节点和要求，不请求模型。「发送并开始」仅运行选中节点。原有聊天输入、附件和别的文件编辑内容不受影响；交接当前未保存文件时先保存，保存失败停止操作并保留草稿。

「接收方式」可选择同项目、同工作流版本、同节点和执行者的已有任务进行补充。补充会创建关联处理记录，包含原任务说明与材料；原记录不被覆盖。连续补充最多关联 10 份材料。任务正在执行或等待验收时，新材料保留为草稿，现有运行结束后再从回执中点击「开始此节点任务」。不会自动排队调用模型。

执行前检查上游交付、当前工作流版本、成员资格和文件内容版本；配置改变后保留说明，刷新目标并重新选择。执行输入保存在项目 `.handoffs/<交接 ID>/` 中，原文件之后的编辑不会改变该次输入。已准备但尚未开始的文件发生变化时，需要重新准备。

团队任务与文件回执引用同一工作流运行。产物生成后按节点配置验收；团队任务完成不替代节点验收。验收只交付本节点，后续节点的执行仍由用户控制。失败、中断和退回可在回执中重试，原运行记录与产物引用会保留。

面板支持最多两个常用目标和三个最近目标，按项目与工作流隔离；常用目标显示在文件工具栏。目标改名后使用新名称，停用或移出工作流后不再显示。文件工具栏显示最近交接状态，「交接记录」可查看历史、运行标识、团队任务、验收结果和产物。

本次实现以单次交接一个项目内文件为范围。文件夹、多文件批量投递及「复制后修改」不在此版本中。更新涉及数据库迁移和后端路由，需重启源码服务与桌面窗口；旧安装包需重新构建后才能包含这些更改。

验证记录（2026-10-26）：13 项后端交接测试、7 项 Edge 界面测试通过，覆盖只读目标查询、越界请求、动态配置、保存失败、补充任务、输入快照、节点验收、常用目标和跨项目延迟响应。相关执行、设置、待办与文件操作回归通过，JS 语法、页面 ID 和主题检查通过。首次全量执行 691 项，出现 6 项旧选择器、路径契约或异步等待问题；修正测试适配后，原失败项所属模块 28 项复测通过。最后的目录隔离改动另通过 9 项界面回归；未再次完整重跑 691 项。
