论文全周期笔记分类与提示词模板实施计划（精简分类版）

日期：2026-10-26。本版按用户最新要求修订：默认少量大类，标签使用可搜索多选下拉框，并允许自行创建和修改一级、二级分类。本版替代此前的固定分类方案；已按本方案完成主要实现，回归结果见文末实施记录。

**1. 核心决定**

采用“默认 5 个一级分类 + 可自定义的二级分类 + 多选下拉标签”。五类是初始配置，不是数量上限。每篇笔记只归属一个分类节点，可直接放在一级分类，也可放在二级分类，不要求必须细分。标签可选、可多选；默认不预建二级分类。

默认五个一级分类为：研究规划、文献研究、实验分析、写作投稿、提示词模板。它们覆盖一般论文项目的规划、文献、实验分析、写作发表以及指令复用需求；属于适合起步的产品设计，不代表所有学科和团队都只需要五类。

实验日志、代码复现、图表图注、讨论决策、审稿返修、成果归档等默认用标签表达。用户需要长期单独管理时，可以新建对应一级或二级分类。自定义二级分类是额外组织能力，不把之前的细分类全部预建回来。

本次补齐论文全周期的笔记组织和模板复用能力。论文正文、数据、代码及最终产物继续由现有模块管理，笔记通过链接或资产引用关联它们。

**2. 五个大类的职责**

| 大类 | 包含内容 | 标签示例 |
|---|---|---|
| 研究规划 | 选题、研究问题、创新性、目标、技术路线、项目推进、讨论与决策 | 选题、创新点、研究假设、技术路线、组会纪要、研究决策 |
| 文献研究 | 文献检索、阅读、证据整理、跨论文综合和文献情报 | 检索策略、精读、文献矩阵、综述、每日推送、研究缺口 |
| 实验分析 | 实验设计与执行、数据处理、计算与复现、结果解释、图表准备 | 实验方案、实验日志、数据清洗、代码复现、统计分析、图表图注 |
| 写作投稿 | 提纲与写作、翻译润色、稿件审查、投稿返修、发表归档 | 大纲、正文、翻译、润色、审稿、返修、投稿、校样、成果归档 |
| 提示词模板 | 可供人和 Agent 重复使用的任务指令 | 检索、精读、实验设计、结果解读、写作、审稿、返修 |

五类是否够用，以实际使用为准：一般论文项目可先使用默认五类；如果存在独立管理的内容集合，例如长期的“课题协作”或大量“复现任务”，用户可以增加一级分类，或在实验分析下面新建“代码复现”二级分类。不能仅凭科研阶段是否齐全就断言所有项目的组织需求都已满足。

标签示例用于帮助理解，不要求全部预先创建，也不要求每篇笔记把相关标签全部加上。每类只提供少量常用建议，其余按使用情况产生。

研究规划偏“研究什么、如何推进”；实验分析偏“具体怎么做、实际得到什么”。一篇笔记涉及多个阶段时，按主要用途选一类，用标签补充另一阶段，不复制成多份。

图表准备和数据来源说明放实验分析；正文中的图表论证和审稿修改放写作投稿。判断依据是笔记的主要目的，不根据单个关键词自动决定。

提示词模板单列，是因为它有“应用为任务指令”的使用方式。普通笔记加上“写作”或“模板”标签，不会自动变成提示词模板。

**自定义一级、二级分类规则**

分类管理放在笔记页面的“管理分类”入口，不新增主导航页面。支持以下操作：

| 操作 | 行为 |
|---|---|
| 新建一级分类 | 输入名称即可加入侧栏，数量不限制为五个 |
| 新建二级分类 | 在任意一级分类下创建子类，不要求同时创建标签 |
| 修改分类 | 默认类与自建类均可改名、调整顺序和说明，分类 ID 不变 |
| 调整层级 | 二级分类可移到另一个一级下或提升为一级；无子类的一级可降为二级 |
| 有子类的一级调整层级 | 需要先处理其子类，界面说明受影响内容；服务端拒绝产生三级层级或循环 |
| 删除分类 | 空分类直接删除；非空分类先选择笔记去向并处理子类，不连带删除笔记文件 |
| 项目复用 | 当前项目独立管理；可将分类方案设为新项目默认，已有项目不被联动修改 |

首版明确支持两级，不开放任意深度。分类属于同一项目；同一父级内名称不能重复，不同父级可同名，选择器显示完整路径用于区分。

选择一级分类时，列表包含该类直接归属的笔记和其二级分类中的笔记；选择二级只显示该二级内容，父级统计不能重复计数。笔记保存一个 category_id，父级通过分类关系推导，不保存两套互相矛盾的归属。

分类是固定的内容分组，标签是跨分类的描述。例如“实验分析 / 代码复现”可同时使用“环境配置”“失败记录”等标签。无需把每个标签都建成分类。

提示词模板默认类也允许改名和建立子类，例如“提示词模板 / 写作”“提示词模板 / 审稿”。模板能力由笔记的模板类型与稳定 ID 决定，不依赖分类显示名称。模板移到其他分类后仍可被 Agent 引用；普通笔记仅移动到模板分类不会自动变成指令。

**3. 标签交互**

创建普通笔记只需要标题、内容和一个归属分类；二级分类与标签都可不选。通常添加 1–3 个标签即可，不强制填写阶段、状态、来源、方法等多组字段。

- 编辑器标题下增加“分类选择 + 标签下拉框”。分类以一级/二级路径展示，标签使用带搜索的多选下拉，不要求用户手动输入标签名。
- 点击标签框即展开复选列表，优先显示当前分类常用和最近使用的标签，再列出当前项目其余标签，去重显示。
- 勾选后保持下拉打开，方便连续选择；已选标签显示为可移除的小标签，支持取消单项与清空。
- 输入文字过滤选项；无同名结果时显示“新建标签：某名称”，用户明确点击后创建并选中。已有同名标签直接复用。
- 支持键盘打开、上下移动、选择和关闭，关闭下拉不会发送任务或提交笔记；跟随现有笔记保存机制持久化所选标签。
- 列表显示标题、少量标签和更新时间；标签较多时折叠展示。
- 点进分类后，顶部使用同样的标签多选下拉筛选，可展示少量常用快捷标签。例如“文献研究 + 精读”就是精读笔记视图。
- 搜索覆盖当前项目的标题、正文和标签，可组合大类与标签过滤。首版多个已选标签按“同时满足”处理，明确显示当前条件。
- 标签在项目内复用，同一个“返修”标签可以用于写作笔记和提示词模板；通过大类区分用途。
- 保存时清理标签首尾空白和可选的 # 前缀，去重并统一大小写匹配；不自动合并不同含义的词。
- 支持批量添加/移除标签。标签重命名和删除只改变标签关联，不删除笔记。
- 侧栏树只展示一级分类和用户自己创建的二级分类；不把标签展开为常驻侧栏树，也不根据标签自动创建目录。

自动标签先使用确定的来源规则，例如精读工具输出加“精读”，日报输出加“每日推送”。自由书写的笔记保持用户选择，AI 建议标签可后续再加。

| 文献矩阵 | 文献研究 | 文献矩阵 |

页面初始导航显示五个默认一级分类；用户创建的一级、二级分类随后加入同一分类树。另有“全部笔记”和“待整理”两个辅助视图，它们不是业务分类。旧分类不再作为另一组历史分类常驻侧栏。

**5. 兼容旧文件，不批量搬动**

新笔记按归属分类创建在“笔记/<一级分类>/<UUID>.md”或“笔记/<一级分类>/<二级分类>/<UUID>.md”。显示名称与合法目录名分开处理，路径仍经过现有校验。旧笔记保留原文件位置和资产 ID，通过旧目录映射得到默认分类与初始标签，不批量搬动文件、不破坏已有路径引用。

分类视图按笔记元数据和可编辑的分类树聚合，不再完全以物理文件树充当分类。否则文件没有搬动，旧的十个类别就会继续出现在主导航，无法达到精简效果。笔记详情保留文件位置查看；原目录中的子文件也纳入映射后的分类。

分类解析优先级为：文件中用户明确保存的 category_id → 旧目录映射或新目录默认值 → 待整理。用户保存分类后，原目录名不能再覆盖其选择。明确保存的 ID 已失效时显示待整理并指出原因，不擅自根据路径换成另一个分类。

标签解析时，文件已有 tags 字段就以该字段为准，空列表表示用户明确清空；只有缺少该字段的旧笔记才采用目录映射的初始标签。用户删除迁移标签后，下次刷新不能重新自动加回。

旧 Markdown 没有结构化头信息时仍可阅读。首次显式编辑分类/标签并保存时，才将元数据写回文件；只读项目只计算映射，不改动文件。自建目录不强行按名称猜分类，未知笔记进入待整理，由用户批量归类。

以后修改分类名称、层级或笔记归属，只改变逻辑组织，不强制移动文件。文件夹整理不作为本次升级的前置功能。删除分类前先检查影响并完成笔记迁移和子类处理；迁移未完成时保留分类，避免出现悬空引用。旧目录映射同步更新，不会因刷新又创建被用户删掉或改名的默认类。

**6. 提示词模板的首版体验**

首版允许用户像写笔记一样保存提示词：填标题、写正文、按需加标签即可。变量和高级设置均可选，不要求每条模板先配置复杂表单。

提供新建、编辑、复制、引用到 Agent 和使用记录。复制生成新 ID，保留来源，不与原模板共享身份。

支持两种模板：

- 固定文本：例如“请从逻辑、证据、表达三个方面检查下列段落”，使用时附上本次材料。
- 带变量：例如“请针对 {{research_question}} 评审 {{experiment_plan}}，重点检查 {{focus}}”。使用时填写变量，可从明确的项目上下文填入研究问题等字段。

引用入口有三个：模板详情中的“引用到 Agent”；Agent 输入框中的“引用模板”；自然语言指定“使用某模板完成这项任务”。选择器支持按名称和标签搜索。

使用流程为：选择模板 → 选择或填写本次材料 → 检查缺失变量 → 发送任务 → 查看结果和使用版本。输入框显示模板名称与版本卡片，让用户看见本轮使用了什么。

首版一次任务使用一个主模板，库中的其他模板不会自动应用。输出按实际用途保存，例如返修回复进入写作投稿并加“返修”标签，不存回提示词模板。

模板标签仍只负责查找。是否绑定到助手、节点或定时任务由明确配置决定，不根据“写作”等标签自动改变 Agent 行为。

**7. Agent 引用与默认绑定**

当前已有 project_note_list、project_note_read、project_note_write 工具，需要增加模板专用语义以处理变量和版本。计划新增三个只读工具：

| 工具 | 职责 |
|---|---|
| prompt_template_search | 在当前项目按名称和标签查找可用模板，返回摘要与稳定 ID |
| prompt_template_read | 读取指定模板的正文、变量与版本 |
| prompt_template_render | 校验变量，生成本次指令及输入来源清单，不自行启动另一个 Agent |

用户明确要求使用模板时，Agent 可直接调用这些工具；只有重名或缺必填信息时需要澄清。界面选择和工具调用共用模板服务。

每次运行锁定模板 ID、资产版本、内容哈希和填入变量，记录输入资产与输出结果。编辑模板不改变正在运行的任务；暂停恢复沿用原快照。复用现有资产版本系统，不另建一套版本存储。

模板正文作为任务要求传入，参考资料保持资料身份；模板不能扩大权限和工具白名单。团队上下文、研究证据检索默认排除未选用的提示词模板，避免模板被当成研究事实或自动启用的指令。

基础引用完成后加入默认绑定：工作流节点、当前项目中的助手/团队成员和定时任务可以指定模板。本次显式选择优先；多个层级同时配置时依次选择工作流节点、团队成员、当前项目助手绑定、项目默认绑定，不拼接多个完整模板。

绑定记录目标项目，防止切换项目后带入其他项目的模板。首版做项目内模板，跨项目通过复制/导入复用；全局模板库后续单独扩展。已设置的绑定在后续运行中直接使用，无需重复确认。

**8. 最小数据与保存设计**

普通笔记新增的用户可见元数据只有归属分类和标签。五个默认分类的稳定 ID 为 planning、literature、experiment_analysis、writing_submission、prompt_templates；自建分类分配新 ID，不能把这五个值作为封闭枚举。不再增加一套必须填写的阶段、来源、状态分类。

分类定义至少包括 id、parent_id、name、description、sort_order、preset_key。parent_id 为空表示一级，否则必须指向同项目的一级分类；写入时校验名称、父节点、循环和两级深度。preset_key 只用于默认类识别与旧入口兼容，显示名称可以修改。

分类方案以项目“笔记/分类配置.json”为权威配置，数据库维护可重建索引。初始化时一次性放入五类，后续以用户配置为准，不在每次启动时补回已删除或重命名的分类。采用原子写入和版本冲突校验；项目导出/复制同时携带这份配置。设为新项目默认时保存独立的方案快照，新项目使用快照初始化，不与原项目建立持续联动。

元数据通过 YAML frontmatter 随 Markdown 保存，使用现有 PyYAML 解析；资产 metadata 是可重建索引，不作为独立修改的第二份定义。旧笔记按第 5 节兼容读取。

普通笔记示例：

~~~yaml
---
category_id: experiment_analysis
tags: [实验日志, 对照实验, 失败记录]
---
~~~

模板在此基础上按需增加 note_type: prompt_template、稳定 template_id 和可选变量定义。运行版本来自 asset_revisions，不要求用户手填版本号。标题继续与现有笔记标题机制一致，由统一保存函数同步。

资产继续使用 kind='note'，以 note_type 区别模板，减少对已有查询和图谱的影响。模板身份、引用和证据过滤依赖 note_type 与稳定 ID，不能依赖分类名称或所在层级。从模板入口新建时默认设置模板类型；现有普通笔记需要通过“存为提示词模板”显式转换或创建模板副本，仅移动分类或添加标签不改变类型。

标签过滤首版通过资产元数据索引实现，不建立复杂标签层级系统。统一索引覆盖文件刷新、兼容数据库回退查询和语义检索。外部编辑后刷新索引；模板使用前校验哈希，定义无效时明确报错。

变量只做声明字段的替换，不执行表达式或脚本。资料引用按当前项目边界解析，缺失必填项返回字段级错误。普通花括号和数学内容不应被误替换。

现有前端新建笔记会在正文前补一级标题；需调整为在 frontmatter 后处理标题，保证带标签的普通笔记和模板均不损坏 YAML。

**9. 实施阶段与文件范围**

按四个可独立验收的阶段推进：

| 阶段 | 内容 | 完成标准 |
|---|---|---|
| 第一阶段：分类与标签 | 默认五类、自定义两级管理、旧目录映射、标签多选下拉/搜索/批量操作、聚合视图 | 默认简洁，分类可扩展；新旧项目均可使用，旧文件无需搬动 |
| 第二阶段：模板与手动引用 | 模板编辑、固定文本和变量、输入框选择器、版本记录 | 用户能保存模板并用于一次实际 Agent 任务 |
| 第三阶段：Agent 自主引用 | 三个工具、结构化参数、模板与证据隔离、恢复快照 | Agent 能发现并应用模板，过程可追溯 |
| 第四阶段：自动化与验收 | 步骤/助手/团队/定时绑定、导入复制、完整回归 | 各入口行为一致，原有笔记与科研流程正常 |

改动按职责集中：

- 新增 note_catalog.py：默认五类、项目分类配置读写、一级/二级校验、旧类映射和建议标签；前后端共用同一动态分类来源。
- project_notes.py、workflow_db.py、workflow_search.py：统一读写、归类和初始化，保留只读、文件边界和并发哈希保护。首次索引在明确的升级/刷新步骤执行，不在浏览页面时批量改文件。
- asset_service.py：保存和索引分类/标签/模板子类型，复用版本；旧保存入口必须保留新元数据。
- notes-and-settings.js：动态两级分类树、分类管理、聚合列表、可搜索的标签多选下拉、模板入口、文件位置查看。
- 新增 prompt_templates.py：解析、查找、变量校验、渲染和版本解析；API 与 Agent 共用。
- workflow_prompts.py、workflow.py、agent_settings.py、HTTP handlers 与聊天界面：工具注册、引用传递、使用版本展示、只读权限处理。
- semantic.py、space_service.py、workflow_documents.py、team.py：区分研究材料和模板，回退检索也遵循一致过滤。
- workflow_runners.py、workflow_layout.py、schedule.py、agent_jobs.py 和配置界面：第四阶段接入默认绑定、排队、重试和恢复。绑定用轻量独立表，避免被节点定义清洗丢弃。

只预置五个一级分类，不预置二级分类；用户可以自行增改一级和二级分类。不新增独立“标签库”主页面，不强制 AI 自动分类，不把全局模板分享和模板组合纳入首版。

**10. 验收标准**

| 场景 | 预期行为 |
|---|---|
| 默认分类 | 初始为五个一级分类，无预设二级；全部笔记、待整理只是辅助视图 |
| 自定义分类 | 可新增第六个一级和任意一级下的二级，刷新/重启后保留；二级不是必选项 |
| 分类层级 | 支持合法移动与升降级，同父级重名、循环、跨项目父节点和三级结构被拒绝 |
| 分类修改 | 改名、排序和移动不改变笔记身份、路径或模板引用；旧生产者按稳定 ID 找到改名后的默认类 |
| 分类删除 | 先处理笔记和子类再删，不连带删文件，不产生悬空 ID，刷新不重建已删除默认类 |
| 分类方案 | 项目配置相互独立，设为新项目默认只影响此后创建的项目，导出携带完整分类配置 |
| 旧分类归并 | 精读、矩阵、综述出现在文献研究中，能分别按标签筛选 |
| 原文件兼容 | 原路径、标题、论文绑定、资产 ID 与内容有效，外部路径引用不因升级失效 |
| 标签可选 | 不加标签也能保存；多个标签不产生多个文件副本 |
| 标签下拉 | 可搜索、多选、取消、清空，支持键盘操作；点击新建才创建标签，同名直接复用 |
| 标签修改 | 已删除的迁移标签不会重新补回，清空标签有效 |
| 自建目录 | 未知内容进入待整理，批量归类后保留原路径，不新增常驻历史分类区 |
| 检索与统计 | 一级包含自身和二级笔记，二级只含自身；分类与标签筛选正确，每篇只计一次，前端/资产/回退查询一致 |
| 多入口保存 | 手写、导入、精读、审查、Agent 采用统一规则，旧接口不会清空元数据 |
| 模板易用性 | 无变量的固定文本也可直接保存和引用，高级配置不阻挡基本使用 |
| 实际应用 | 模型收到渲染后的任务要求，界面显示本轮使用版本 |
| 模板身份 | 仅加标签或移动到模板分类不会变成指令；模板类改名、模板移入二级或其他类仍可引用；复制模板有新身份 |
| 缺失与失效 | 必填项缺失或显式绑定失效时明确报错，不静默执行其他模板或无模板任务 |
| 版本与恢复 | 修改不影响旧运行，暂停恢复和同一任务重试继续使用快照 |
| 资料与指令 | 未选用模板不进入团队默认上下文、研究证据或论证谱系 |
| 原功能回归 | 自动保存、导入导出、只读/冲突保护、工作流和团队任务正常 |
